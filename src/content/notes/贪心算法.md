# 贪心算法

<u>贪心算法（greedy algorithm）</u>是一种常见的优化问题求解方法，其核心思想是在每个决策阶段选择当前看起来最优的局部选择，以期最终获得全局最优解。贪心算法逻辑简洁、实现高效，在许多实际问题中有广泛应用。

贪心算法与动态规划都常用于解决优化问题，两者都依赖最优子结构性质，但工作原理不同：

- **动态规划**：综合考虑之前所有阶段的决策，利用已解子问题的结果构建当前子问题的解。
- **贪心算法**：不回溯过去的决策，每步做出贪心选择，逐步缩小问题规模，直至问题解决。

## 优点与局限性

**贪心算法操作直接、实现简单，且通常效率很高。** 以硬币找零为例，设硬币最小面值为 $\min(coins)$，贪心选择最多循环 $amt / \min(coins)$ 次，时间复杂度为 $O(amt / \min(coins))$，比动态规划的 $O(n \times amt)$ 小了一个数量级。

然而，**对于某些硬币面值组合，贪心算法并不能找到最优解**，以下是两个反例：

- **正例** $coins = [1, 5, 10, 20, 50, 100]$：对任意 $amt$，贪心算法均能找到最优解。
- **反例** $coins = [1, 20, 50]$，$amt = 60$：贪心算法得到 $50 + 1 \times 10$，共 11 枚硬币；动态规划可找到最优解 $20 + 20 + 20$，仅需 3 枚。
- **反例** $coins = [1, 49, 50]$，$amt = 98$：贪心算法得到 $50 + 1 \times 48$，共 49 枚硬币；动态规划可找到最优解 $49 + 49$，仅需 2 枚。

由此可见，贪心算法无法保证零钱兑换问题的全局最优解，该问题更适合用动态规划求解。

一般而言，贪心算法的适用情况分两类：

1. **可以保证最优解**：此时贪心算法往往是首选，通常比回溯或动态规划更高效。
2. **可以找到近似最优解**：对于难以求得全局最优解的复杂问题，以较高效率获得次优解同样具有实用价值。

## 贪心算法的适用条件

什么样的问题适合用贪心算法求解？相较于动态规划，贪心算法的使用条件更为苛刻，主要关注以下两个性质：

- **贪心选择性质**：局部最优选择能够始终导向全局最优解。
- **最优子结构**：原问题的最优解包含子问题的最优解。

最优子结构在动态规划章节中已有介绍，此处不再赘述。值得注意的是，部分问题的最优子结构并不直观，但仍可使用贪心算法求解。

贪心选择性质的判断是难点所在。虽然描述简单，**但对许多问题而言，证明贪心选择性质并非易事**。以零钱兑换为例，举出反例进行证伪相对容易，但若要证明"满足何种条件的硬币组合可用贪心算法求解"，往往难以给出严谨的数学证明，只能依赖直觉或举例佐证。

## 解题步骤

贪心问题的求解流程大体分为以下三步：

1. **问题分析**：梳理问题特性，明确状态定义、优化目标与约束条件。
2. **确定贪心策略**：设计每一步的贪心选择方式，使问题规模逐步缩小直至解决。
3. **正确性证明**：证明问题具备贪心选择性质和最优子结构，通常借助数学归纳法或反证法。

确定贪心策略是核心步骤，实施难度较高，原因主要有两点：

- **不同问题的贪心策略差异较大**：简单问题的策略较为直观，复杂问题的策略则可能十分隐蔽，高度依赖解题经验与算法能力。
- **某些贪心策略具有迷惑性**：设计好的策略提交后，可能因策略"部分正确"而无法通过全部测试用例，零钱兑换问题便是典型案例。

为保证正确性，应对贪心策略进行严谨的数学证明，**通常使用反证法或数学归纳法**。若无思路，也可通过针对测试用例的调试逐步修正和验证策略。

## 典型例题

贪心算法常应用于满足贪心选择性质与最优子结构的优化问题，以下是几类典型场景：

- **硬币找零问题**：在特定硬币组合下，贪心算法可得到最优解。
- **区间调度问题**：给定若干时间段任务，目标是完成尽可能多的任务。每次选择结束时间最早的任务，贪心算法可得最优解。
- **分数背包问题**：给定物品与载重限制，目标是最大化总价值。每次选择性价比（价值/重量）最高的物品，贪心算法在部分情况下可得最优解。
- **股票买卖问题**：给定历史股价，允许多次买卖（持有期间不可重复买入），目标是最大化利润。
- **霍夫曼编码**：一种无损数据压缩的贪心算法。通过构建霍夫曼树，每次合并出现频率最低的两个节点，最终使编码的带权路径长度最小。
- **Dijkstra 算法**：求解单源最短路径问题的贪心算法，每次从未访问节点中选取当前距离最短的节点进行扩展。
