## Vue 的 diff 算法详解（Vue 2 与 Vue 3 对比）

Vue 使用虚拟 DOM（Virtual DOM）来描述真实 DOM 结构。当组件状态变化时，会生成一棵新的虚拟 DOM 树，然后通过 **diff 算法** 对比新旧两棵树的差异，并计算出最小化的 DOM 更新操作，从而高效地更新视图。Diff 算法是虚拟 DOM 性能优化的核心。

### 一、Vue 2 的 diff 算法

Vue 2 的 diff 算法基于 **Snabbdom** 实现，采用 **双端比较（双指针）** 策略，只进行同层级的节点比较（不跨层级）。

#### 1. 基本流程
- 对新旧两个 VNode 数组（子节点列表）分别设置四个指针：
  - `oldStartIdx`、`oldEndIdx`：旧子节点数组的开始和结束索引
  - `newStartIdx`、`newEndIdx`：新子节点数组的开始和结束索引
- 同时维护对应的四个 VNode 引用：`oldStartVNode`、`oldEndVNode`、`newStartVNode`、`newEndVNode`。
- 在 `while` 循环中，只要旧开始索引 ≤ 旧结束索引 且 新开始索引 ≤ 新结束索引，就进行以下四种比较（优先顺序）：
  1. **旧开始 vs 新开始**：若 `sameVnode(oldStartVNode, newStartVNode)`，则直接复用旧节点，递归更新其属性和子节点，然后两个指针同时向后移动。
  2. **旧结束 vs 新结束**：若相同，则复用并递归更新，两个指针同时向前移动。
  3. **旧开始 vs 新结束**：若相同，说明节点被移动到右边，复用节点并更新，将旧开始节点移动到旧结束节点之后（真实 DOM 移动），然后旧开始指针后移，新结束指针前移。
  4. **旧结束 vs 新开始**：若相同，说明节点被移动到左边，复用节点并更新，将旧结束节点移动到旧开始节点之前（真实 DOM 移动），然后旧结束指针前移，新开始指针后移。
- 如果四种比较都不匹配，则进入 **key 查找模式**：
  - 若新开始节点有 `key`，则在旧子节点中查找相同 `key` 的节点（通过 `createKeyToOldIdx` 映射）；若找到且 `sameVnode`，则复用并移动到旧开始位置，然后更新；否则创建新节点插入到旧开始位置。
  - 若没有 `key`，则只能遍历旧子节点查找 `sameVnode`（通常通过标签名等判断），效率较低。
- 循环结束后，处理剩余节点：
  - 若旧节点有剩余（`oldStartIdx > oldEndIdx`），说明新节点多出，需要批量创建并插入。
  - 若新节点有剩余（`newStartIdx > newEndIdx`），说明旧节点多出，需要批量删除。

#### 2. `sameVnode` 的判断
```javascript
function sameVnode(a, b) {
  return (
    a.key === b.key &&
    a.tag === b.tag &&
    a.isComment === b.isComment &&
    isDef(a.data) === isDef(b.data) &&
    sameInputType(a, b) // 针对 input 的 type 判断
  )
}
```
只有 key 和标签等相同才会认为是“同一个节点”，从而复用。

#### 3. 优缺点
- **优点**：算法简单清晰，能够有效减少 DOM 操作，特别是对于头尾节点的变动处理较快。
- **缺点**：
  - 对于中间节点的乱序移动处理不够高效，可能需要较多遍历。
  - 没有利用编译时信息，所有节点都需要参与 diff。
  - 没有 key 时容易导致错误复用（例如输入框状态错乱）。

### 二、Vue 3 的 diff 算法

Vue 3 在编译阶段对模板进行静态分析，生成带有 **PatchFlag** 的渲染函数，并在运行时结合 **动态子节点收集（Block Tree）** 和 **最长递增子序列** 进行更高效的 diff。

#### 1. 编译时优化
- **静态标记**：对模板中的静态节点（如纯文本、不含动态绑定的元素）进行标记，这些节点在更新时会被直接跳过，不再参与 diff。
- **PatchFlag**：动态节点会携带一个数字标记（如 `1` 表示动态文本，`2` 表示动态 class 等），在 diff 时只需要比较标记对应的属性，而不是整个节点所有属性。
- **动态子节点收集**：Vue 3 引入了 **Block** 概念，将动态子节点收集到 `dynamicChildren` 数组中。更新时只需对 `dynamicChildren` 进行 diff，静态部分完全忽略。

#### 2. 子节点 diff 的核心算法
Vue 3 处理子节点数组时，不再使用双端比较，而是采用了更高效的 **最长递增子序列（LIS）** 算法，以最小化 DOM 移动次数。

具体步骤（以新旧两组子节点为例）：
1. **处理相同的前缀**：从头开始比较，遇到 `sameVnode` 就复用并更新，直到遇到不同的节点。
2. **处理相同的后缀**：从尾部开始比较，遇到 `sameVnode` 就复用并更新，直到遇到不同的节点。
3. **处理中间部分**：
   - 如果新节点中间部分为空，则删除旧节点中间部分。
   - 如果旧节点中间部分为空，则创建新节点中间部分并插入。
   - 否则，进入复杂场景：
     - 为新节点中间部分建立 `key -> index` 的映射。
     - 遍历旧节点中间部分，通过 key 查找新节点中是否存在相同节点：
       - 若存在，则复用节点并更新，记录该新节点在旧节点中的索引，同时标记该新节点已被匹配。
       - 若不存在，则删除旧节点。
     - 遍历结束后，找出新节点中未被匹配的节点，创建并插入。
     - 计算已匹配的旧节点索引的 **最长递增子序列**，该序列中的节点在更新后不需要移动位置；其余节点则需要移动到正确位置（通过 `insertBefore` 实现）。

#### 3. 最长递增子序列的作用
例如旧节点中间部分为 `[A, B, C, D]`，新节点中间部分为 `[D, A, B, C]`。匹配后旧节点在新节点中的索引为 `[3, 0, 1, 2]`（对应 `A:3, B:0, C:1, D:2`，注意排序）。实际上算法会得到一个索引数组，求其 LIS，假设 LIS 是 `[0, 1, 2]`（对应 B, C, D 相对顺序不变），则只需要将 A 移动到末尾即可，减少了不必要的移动。

### 三、Vue 2 与 Vue 3 diff 算法的区别

| 对比项               | Vue 2                                   | Vue 3                                   |
| -------------------- | --------------------------------------- | --------------------------------------- |
| **算法核心**         | 双端比较（双指针）                      | 前缀/后缀处理 + 最长递增子序列          |
| **编译时优化**       | 无（运行时纯 diff）                     | 静态标记、PatchFlag、Block Tree         |
| **静态节点处理**     | 会递归进入静态节点进行 diff（但可能缓存） | 完全跳过静态节点，只 diff 动态节点      |
| **动态属性更新**     | 全量比较节点所有属性                    | 根据 PatchFlag 只比较变化的属性         |
| **列表移动效率**     | 中间乱序移动需要较多操作                | 通过 LIS 最小化移动操作                 |
| **key 的重要性**     | 非常重要，无 key 时退化严重             | 同样重要，但结合编译优化后整体更健壮    |
| **内存与性能**       | 较低效                                  | 更高效，尤其在大列表和复杂组件中        |
| **引入的新概念**     | 无                                      | Block、dynamicChildren、PatchFlag、LIS  |

#### 总结
Vue 3 的 diff 算法通过 **编译时优化 + 运行时更智能的节点复用与移动策略**，大幅提升了更新性能。Vue 2 的双端比较算法虽然经典，但在复杂场景下不如 Vue 3 高效。理解两者的差异有助于我们在实际开发中选择合适的版本，并更好地利用 key 等特性优化应用性能。
