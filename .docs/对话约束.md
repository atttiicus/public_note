### 要求1

用户会事先创建一个 .docs/问题.md 文件，用于表示用户当前提到遇到的问题。

所以当用户说：「处理一下问题」时，你应该根据 .docs/问题.md 文件中的内容，来处理问题。

### 要求2

问题处理完毕后，请进行记录，记录到 .docs/问题处理结果.md 文件中。

格式为：

```markdown
## 用户提出的问题（如果过长则适当简写，保证问题的完整性和准确性）

- 你的最终处理方案（同样如果过长则适当简写，保证方案的完整性和准确性，但不要超过 500 字）

- 最终处理结果

***

## 下一个问题

- 下一个处理方案

- 下个问题的处理结果

***
```

### 要求3

当用户要求里输出 XXXXX 文档时，默认将输出的文档放在 .docs/ai_output/ 目录下。

### 要求4

面对用户的问题，你需要进行详细分析并确定问题的核心关键，同时根据问题给出相应的解决方法（如果有必要可以进行追问，直到真正了解用户需求为止）。

同时应尽量举例出不同的处理方案，每个方案都要详细说明，包括实现步骤、注意事项等。

### 要求5

用户的问题若过于复杂和庞大，请先进行问题的拆分，将问题拆分成多个子问题/子任务，每个子问题/子任务都要详细说明，包括实现步骤、注意事项等。

同时将这个任务列表整理输出到 .docs/tasks_list/ 目录

后续根据这个任务列表来进行逐一处理（每个子问题处理完毕后需要更新这个任务列表）

拆分出来的子问题/子任务，应该用不同的紧急等级进行排列。

格式为：

```markdown
# 子问题1（如果过长则适当简写，保证问题的完整性和准确性）
    - 解决方案1
    - 解决方案2
    - 解决方案3
## 用户选择的处理方案（如果过长则适当简写，保证问题的完整性和准确性）
    - 你的最终处理结果（同样如果过长则适当简写，保证方案的完整性和准确性，但不要超过 500 字）

# 子问题2
    - 解决方案1
    - 解决方案2
    - 解决方案3
## 用户选择的处理方案
    - 你的最终处理结果

# 子问题3
    - 解决方案1
    - 解决方案2
    - 解决方案3
## 用户选择的处理方案
    - 你的最终处理结果
```

### 要求6

如果用户有创建 .docs/ai_read.md 和 .docs/规范/**.md 等文件，请先进行阅读，了解用户的需求和规范。

同时在处理问题之前扫描用户当前安装的 skills 和 MCP 插件，确认用户的那些 skills 和 MCP 插件可以用来处理本项目相关问题。

并整理输出到 .docs/use_skills_mcp.md 文件中。询问用户是否启用这些 skills 和 MCP 插件来辅助处理问题。


### 要求7

当处理问题时，如果涉及代码修改，必须进行测试+重构，确保代码的质量和稳定性。
